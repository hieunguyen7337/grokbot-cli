# Data behind the plan-limit findings

De-identified aggregates and events behind `../FINDINGS.md` §1 (Claude Max 20x) and §2 (Codex Pro Lite and Plus). Kept: timestamps, percentages, token counts, credit and dollar values, model names, block labels, fit results. Dropped: session, request and account ids, paths, prompt and response text. Codex session ids became per-file sequence numbers (`s001`…); Claude events carry a `probe_block` label instead. Rerun commands are in `../../measure/README.md`, "Rerunning the fits from the shipped data".

## claude/

Supports §1 (C-series, 2026-10-19). Every window is a whole-percent rise interval, not a confidence interval.

- `events_cprobes.csv`: 869 deduplicated responses inside the C0–C5 meter windows (ts, model, five token columns, `probe_block`). Input to `analyze_cprobes.py`; supports every Claude number.
- `meter_readings.jsonl`: the 12 `pre-cN`/`post-cN` readings (ts, label, 5h and 7-day utilization). Gives the 5h and weekly rises; supports $254 (5h) and $1,525 (weekly).
- `marks.tsv`: block start and end times. Read by the analyzer for completeness only.
- `extract_report.json`: row count, time span and run time of the lab's full extraction. Only quoted in the regenerated report.
- `fable_window.json`: the Fable window's 0 → 5% reading after C5. Supports Fable's $531 sub-cap. It is not in `meter_readings.jsonl`, so the lab never held it in a file; see "Caveats".
- `derived.json`: the lab's fit output: per-block tokens, list-dollar costs (H1, H2), dollars per 1% with intervals, cache-read weight. Supports the 5h and weekly sizes, the model weights, Fable's sub-cap, the cache weight and the request-fee bound.
- `c_blocks.csv`: `derived.json` flattened, one row per block (rise, cost, dollars per 1% point and bounds). Same findings.
- `c_model_tokens.csv`: `derived.json` flattened, one row per block and model (tokens, cost). Supports Fable's $26.57 and the Opus and Haiku block costs.

## codex/

Supports §2. Credits are rate-card credits (`../findings.json` `rate_card`).

- `events_probes.csv`: 526 token events of the controlled probes P1–P5 (ts, `session_seq`, model, token deltas, `used_percent`). Input to `fit_probes.py`; supports Pro Lite ≈ 8,400 credits and the sol/luna factors.
- `marks.tsv`: P1–P5 start and end times. Input to `fit_probes.py`.
- `meter_readings.csv`: the four live readings around P4 and P5 (14 → 18 → 18%). Cross-check of the event readings.
- `block_summary.csv`, `block_summary.json`: per-block tokens, card credits, meter rise, credits per 1% and quantization bracket. Supports the 8,400 range (P1–P3: 1,010.7 credits over 12 points), the pooled 7,870 (P1–P4), the sol factor 1.36 and luna's bound below 5.8.
- `intervals.csv`: credits between consecutive integer rises inside each block. Supports sol's 1.19 and the token-type ratios.
- `joint_fit.json`: joint fits of the three token types (ways A, B, C) and their intervals. Supports "consistent with the card within about ±25%".
- The fitted tables of the three Plus weeks that reset 2026-09-27, 10-04 and 10-05 (`windows.csv`, `fit_a_b.csv`, `fit_c.csv`) ship, but their 6.4 MB event file stays in the lab, so the Plus fit cannot be rerun from the bundle.
- `windows.csv`, `fit_a_b.csv`, `fit_c.csv`, `unknown_models.json`: passive fit outputs for all 20 observed weeks (all plans). Supports Plus ≈ 1,450 (rows `1790431200`, `1791046800`, `1791198000` of `fit_a_b.csv`) and the superseded Pro Lite 2,700–3,400.

## Caveats

- `claude/derived.json` and `codex/block_summary.*` are regenerated by the kit's own analyzers from the files here. The lab's copies differed in two places: its `model_factors_vs_sonnet` held the reciprocal of each weight (Haiku 0.58, Opus 1.06, Fable 0.49 for `H1_5h`; the report and §1 use 1.72, 0.95 and 2.06, as shipped here), and its P5 (luna) cost-per-point range ended at an invented 145.73, where a block that moved no whole point has no upper bound (`inf`).
- The Fable-window reading is a recorded input, not a regenerated one.
